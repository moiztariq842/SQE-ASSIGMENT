## 1. `Stack` (data_structures/stacks/stack.py) - `__init__`, `push`, `pop`, `peek`

| Function | ECP classes | BVA points | Tests |
|---|---|---|---|
| `__init__(limit)` | default limit; custom positive limit | limit = 0 (first push must overflow) | `TestInit` (7) |
| `push(data)` | valid types: int, str, None, list | stack at limit-1, limit, limit+1 (limit 1, 3, 10) | `TestPush` (9 cases) |
| `pop()` | non-empty (1, 2, 3 items); `None` stored as data | 1 item -> empty -> underflow | `TestPop` (7 cases) |
| `peek()` | non-empty (1, 2, 3 items) | empty stack; after pop; after push-pop-push | `TestPeek` (7 cases) |

Class-level scenarios (`TestStackScenarios`, 5): LIFO order, interleaved push/pop, fill-drain-refill, usable after overflow error, mixed types.
CSV-driven (`test_stack_scenarios_from_csv`, 6 rows from `stack_scenarios.csv`): full stack, partial pop, empty, overflow, underflow, limit 1.

| Function | ECP classes | BVA points | Tests |

## Notes / observations
- `StackOverflowError` / `StackUnderflowError` inherit from `BaseException` (not `Exception`), so they are not caught by a plain `except Exception`. `pytest.raises(...)` with the exact class works.
- `CircularQueue` raises a plain `Exception` with messages `QUEUE IS FULL` / `UNDERFLOW`, so tests match on the message.
